4. 8 Non-Negotiable Architectural Rules

These are final platform requirements. Do not deviate without flagging, explaining the tradeoff, and getting explicit confirmation.

Rule 1 â€” Custom State Machine
No LangChain. No autonomous loops. The journey is a predictable, structured workflow. The Virtual Employee Team is a bounded, orchestrated multi-agent workflow (deterministic fan-out â†’ role agents â†’ fan-in â†’ QA â†’ delivery) on this same state machine â€” not autonomous self-directing loops.
Rule 2 â€” Strict JSON Outputs
All agent outputs are strict JSON validated against a Zod schema before being written to memory or rendered. Reject + retry once on malformed output. This applies to every agent, including all Virtual Employee roles.
Rule 3 â€” Shared Memory Layer
Every agent reads from and writes to one shared UserContext store. Agents are never isolated. The VET additionally shares a project-scoped ProjectContext under the same shared-memory discipline.
Rule 4 â€” Payment Abstraction
The app NEVER talks to a payment gateway directly. Flow: App â†’ PaymentService â†’ Adapter (Razorpay / Cashfree / Stripe / PayPal). Annual billing flows through the same abstraction.
Rule 5 â€” Email/Notification Abstraction
The app â†’ EmailService â†’ Adapter (Resend / SendGrid / SES). Trial-countdown reminders, offer/FOMO notifications, and relationship/renewal reminders are all dispatched through the Notification Service; never by constructing provider payloads inline.
Rule 6 â€” Subscription Plans â‰  Platform Roles
These are two separate axes. A plan (Trial/Pro/Premium/Free) controls customer feature access. A role (Super Admin / Admin) controls platform management. Never merge them into one enum.
Rule 7 â€” Super Admin = Full, Unrestricted, Automatic Access
Super Admin has access to everything â€” all phases, all agents, all dashboards, all analytics, all controls. Zero manual permission assignment, now and for every future feature. Implementation: authorization checks short-circuit to allow when role === 'SUPER_ADMIN' before evaluating any plan/phase/feature-flag logic.
Rule 8 â€” Phase Gating Applies Only to End Users
Admins and Super Admins are never phase-restricted. Phase gating only applies to customer accounts.

export async function guardRequest(userId: string, feature: Feature) {
  const user = await getUser(userId)

  // Rule 7: Super Admin short-circuit
  if (user.role === 'SUPER_ADMIN') return { allowed: true }

  // Admin role checks (no phase-gating)
  if (user.role === 'ADMIN') {
    return checkAdminPreset(user.adminPreset, feature)

  const plan = user.subscription?.plan

  // Phase check
  const requiredPhase = FEATURE_PHASE[feature]
  if (plan !== 'PREMIUM' && requiredPhase > MVP_PHASE) {
    return { allowed: false, code: 'PLAN_REQUIRED', upgradeTrigger: true }
  }

  // Daily usage check
  const usage = await getDailyUsage(userId)
  if (usage.count >= PLAN_DAILY_LIMIT[plan]) {
    return { allowed: false, code: 'DAILY_LIMIT_REACHED', upgradeTrigger: true }
  }

8. AgentRunner â€” 9-Step Execution Pipeline

Every agent call goes through this pipeline in order. Super Admin short-circuits at step 1.

  1. Authorize â€” role/plan/phase/feature-flag check. Super Admin â†’ instant ALLOW.
  2. Check Usage â€” daily AI-output limit for the plan. Reject + upgrade trigger if exceeded.
  3. Read Memory â€” load UserContext (+ optional ProjectContext) from SharedMemoryService.
  4. Build Prompt â€” system prompt from DB AgentConfig + memory context, capped at input token budget.
  5. Call Model â€” claude-sonnet-4-6 (fallback OpenAI). max_tokens = agent's output budget.
  6. Validate â€” parse + Zod-validate strict JSON schema. Retry once on malformed output.
  7. Persist â€” write structured output to shared memory + domain table (e.g., OpportunityRoadmap).
  8. Increment â€” record one AI output against user's IST-keyed daily counter.
  9. Return â€” { data: T, usage: {...}, remainingDailyOutputs: number }
Retry Behaviour
On step 6 failure (malformed JSON): retry step 5 once with an error-correction prompt suffix. On second failure: return { error: "AGENT_OUTPUT_INVALID" }. Never write partial output.
